# 工作人员后台第一批运行说明

> 本文保留第一批身份/权限的历史部署基线。第二、三批的当前功能状态与接口见下方“第二、三批已开放”及 [接口说明](api.md)；第四批工单仍未实现。

## 本批范围

已实现JWT工作人员登录、刷新轮换、退出撤销、七类岗位及事项范围、明确的记录授权读取边界、服务端渲染登录与工作台，以及维护端授权脚本。页面无需JavaScript即可登录、续期和退出。

## 第二、三批已开放

有授权的业务负责人可上传Markdown/PDF教学资料、维护不可变草稿及规则、提交版本包和处理反馈；监督员审核/发布/停用、维护按事项独立的提示词模板，并在显式body记录授权下审计真实对话、风险标记及人工复核。版本包遵守生效区间；同一提交人或内容维护者不能自审。窗口/热线可以按授权查看知识和反馈，但不能维护发布；工程师默认无业务正文。主要入口`/staff/knowledge`、`/staff/rules`、`/staff/reviews`、`/staff/feedback`、`/staff/prompts`、`/staff/audits`。审核发布仅owner/supervisor同事项可见，接口字段和错误见[接口说明](api.md)。

PDF逐页提取失败或扫描空白时仅提示人工补充，不做OCR假结果；含Form XObject的复杂PDF整体拒绝以防部分正文静默成功，可转换为简单教学PDF或另建人工补充版本。人工补充会产生新版本。提取在可终止子进程内并对pypdf预设解压/解析预算，但不是完整生产级恶意PDF沙箱，尤其Windows需在真实客户部署加Job Object/容器内存、权限与隔离约束。任务队列持久化、过期租约可恢复，索引与源文件写仓库外运行目录。

公开问答在接纳事务冻结提示词和适用公开发布版本，两类教学事项均可由负责人配置；居住证首次后台发布前仍可使用原本地教学指南，发布后若全部停用不会恢复旧指南。`workflow`仅内部可见，不进入公开问答。历史引用保留；模型协议错误/索引损坏不会伪装成依据不足。未接入预检，不造预检记录；第四批人工工单尚未实现。真实外部模型、生产密钥、真实客户资料未经联调或授权，不声称99%达标。

现有办事人登录、匿名咨询与历史消息继续使用原表和原Cookie，未改为工作人员凭证。

## 启动与密钥

Python 3.11+，先安装最新依赖。在仓库根目录的同一个PowerShell终端执行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:PYTHONPATH = (Resolve-Path src).Path

# 数据库与运行文件放在仓库外的私有目录；维护脚本与服务须使用同一配置。
$env:ZHENGWU_RUNTIME_DIR = Join-Path $env:LOCALAPPDATA 'ZhengwuRuntime'

# 本机演示生成独立随机密钥，结果只赋给环境变量，不打印或写入仓库。
$env:ZHENGWU_STAFF_JWT_SECRET = .\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"

.\.venv\Scripts\python.exe -m zhengwu_precheck.main
```

访问 [工作人员登录](http://127.0.0.1:8000/staff/login)。没有默认工作人员账号。

上述密钥生成命令每次执行都会更换密钥，使旧JWT失效；持续部署应通过仓库外安全配置向进程提供稳定的独立密钥。密钥至少32字节，不能与其他系统共用。未配置或过短时后台登录返回503说明，公开咨询仍正常。

HTTPS部署应设置 `ZHENGWU_SECURE_COOKIES=true`，并配置实际域名 `ZHENGWU_ALLOWED_HOSTS`。默认本机HTTP演示不启用Secure。JWT签名不提供载荷加密，载荷只含账号ID、会话ID、随机标识、授权版本与时效，不放材料或密码。

## 创建账号与配置岗位

先停止占用当前终端的服务，或在另一个具有相同运行目录配置的终端执行。账号创建脚本交互输入密码，不把密码放在命令行参数中：

```powershell
.\.venv\Scripts\python.exe scripts/create_user.py your_window_account
.\.venv\Scripts\python.exe scripts/staff_access.py --operator maintenance_person grant-role your_window_account window --matter residence-permit
```

岗位代码及默认范围边界：

| 代码 | 岗位 | 关键限制 |
| --- | --- | --- |
| window | 窗口工作人员 | 未来处理窗口工单；规则只读与反馈，不审核发布 |
| reviewer | 业务审核员 | 专业问题处理，不代替监督员签核 |
| owner | 业务负责人 | 知识、规则草稿维护与提交，不审核自己的版本 |
| supervisor | 数据与流程监督员 | 审核发布、提示词管理及审计；材料原图不默认开放 |
| hotline | 热线人员 | 授权问题摘要及进度，无对话正文、证件原图权限 |
| engineer | 政务平台工程师 | 技术状态，无业务对话或材料正文权限 |
| director | 服务中心主任 | 仅显式授权的事项及记录，不自动拥有全局数据权限 |

事项代码为 `residence-permit`、`sole-trader-registration`；全部事项必须显式传入 `--matter '*'`。即使工程师获全部事项范围，也不会因此拥有材料或业务正文权限。同一人员多个岗位的动作与事项必须来自同一条授权，不能交叉组合。

授权脚本需要维护人员的数据库访问权限，是仓库外运维边界，不是网页权限提升接口。`--operator` 是执行者留痕标识，不是额外的登录凭证；应由获批准的维护人员操作。

撤销岗位或停用后台账号：

```powershell
.\.venv\Scripts\python.exe scripts/staff_access.py --operator maintenance_person revoke-role your_window_account window --matter residence-permit
.\.venv\Scripts\python.exe scripts/staff_access.py --operator maintenance_person disable your_window_account
```

岗位调整会增加授权版本，既有JWT与刷新凭证立即失效，重新登录后才取得新授权。后台停用不删除用户或历史记录。

## 记录授权边界

本批以现有真实会话表验证记录权限，没有创建假材料、假预检或假工单。

```powershell
.\.venv\Scripts\python.exe scripts/staff_access.py --operator maintenance_person grant-record your_window_account CONVERSATION_UUID --level summary
.\.venv\Scripts\python.exe scripts/staff_access.py --operator maintenance_person grant-record your_window_account CONVERSATION_UUID --level body
.\.venv\Scripts\python.exe scripts/staff_access.py --operator maintenance_person revoke-record your_window_account CONVERSATION_UUID
```

summary只允许摘要，body还需要岗位本身具备正文权限及适用事项授权；单独记录授权不会覆盖岗位限制。没有显式记录授权，即使岗位及事项吻合也返回404。

正文接口按每条消息当时的事项快照筛选，不能用会话当前事项覆盖旧历史。会话预览接口仅返回事项明确且完成的问答轮次，未确认、失败或取消轮次不在该预览接口展示；第三批审计已开放，包含真实对话与拒绝事件、人工标记/复核，但仍要求事项权限与显式body记录授权。最多返回100条授权消息，不提供材料下载。

## 已实现接口

| 方法与路径 | 用途 |
| --- | --- |
| GET /staff/login | SSR登录页及独立CSRF令牌 |
| GET /staff | 当前岗位与事项范围工作台 |
| POST /staff/api/auth/login | 表单或JSON登录；表单成功303跳转，JSON只返回状态和CSRF令牌 |
| POST /staff/api/auth/refresh | 刷新轮换，旧刷新凭证不能重复使用；不延长8小时绝对期限 |
| POST /staff/api/auth/logout | 撤销当前会话族并清理后台Cookie，兼容刷新与退出并发 |
| GET /staff/api/me | 当前账号、岗位授权及权限；不返回密钥或令牌 |
| GET /staff/api/system/status | 仅工程师技术权限；不返回用户、材料或业务正文 |
| GET /staff/api/conversations/{id} | 显式授权且事项吻合的会话摘要 |
| GET /staff/api/conversations/{id}/messages | 额外检查正文权限并按消息事项过滤 |

第二、三批知识、规则、审核、反馈、提示词、审计已开放真实业务写接口（见[接口说明](api.md)）；`/staff/tickets`仍为第四批说明页，没有真实工单或分派人员列表。

## 凭证及错误

- JWT固定HS256、签发方zhengwu-precheck、用途zhengwu-staff，有效期最多15分钟；验证必需声明、签名、时效及服务端当前授权版本。
- HttpOnly Cookie `zw_staff_access`、`zw_staff_refresh`、`zw_staff_csrf` 均限定 `/staff`；不会发送到办事人聊天接口。令牌不放localStorage或页面正文。
- 刷新凭证与CSRF随机值只在数据库保存摘要，刷新凭证轮换后旧JWT也不能继续读记录。
- 退出可使用刷新前签名JWT及绑定CSRF撤销同一会话族；必要的CSRF回退只用于注销，不授予读取或刷新能力。
- API错误使用现有统一JSON结构。401表示登录失效；403表示岗位或CSRF拒绝；404表示记录不可见；503表示后台密钥未配置。SSR未登录跳转登录页，表单登录失败返回中文页面。
- 权限和记录访问留痕写入audit_logs，不记录密码、JWT或刷新凭证正文。
