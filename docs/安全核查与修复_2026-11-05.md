| 2. storage.to_path() 路径约束 | 无同名函数。材料路径原先校验 UUID，但非法值会抛未处理异常，且未解析检查最终目标。知识原文/索引读取已有目录检查，生成文件写入缺少同等统一约束 | 新增 `utils/storage_paths.py`，拒绝绝对路径、父目录、Windows 盘符/反斜杠和解析后越界的链接目标；接入材料读写、知识上传、索引及临时文件写入。非法材料 ID 返回受控 404。未证明存在匿名可直接读取任意文件的原始入口，不把防御补强描述为已复现匿名拖库 |
| 3. /api/v1/* 全局默认鉴权 | 无该接口前缀。实际后台业务 API 使用 `/staff/api/*`；现有接口各自执行身份/权限检查，但新增路由可能漏写校验 | 在 FastAPI 全局依赖加入后台 API 默认身份检查，按已匹配路由识别，避免代理挂载前缀漏判。只有准确匹配的 POST 登录、续期、退出入口例外；原 CSRF、会话及细粒度权限校验继续生效。原生工单表单登录失效仍返回无业务内容的 HTML 提示，JSON 接口格式不变 |
| 4. sort 参数白名单 | 未发现将外部 sort 直接拼入 ORDER BY 的代码。工单、知识、审计和日志的排序由固定 SQL 或内部常量决定，业务过滤值使用绑定参数 | 保留固定排序，不新增动态排序功能。增加实际 SQLite 回归，传入恶意排序文本后仍只返回本人记录，注入形式的状态过滤不扩大结果，用户表保持完整 |

## 关键实现与验证入口

- 正式启动：[`release_preflight / check_demo_credentials`](../src/zhengwu_precheck/core/services/operations.py)。只读打开当前运行库，仅检查活动的 `demo_*` 用户是否仍匹配公开示例口令；检查失败则停止正式启动，不重置账号。该检查不是全用户弱口令审计，也不替代其他启动方式的部署管理。
- 文件边界：[`private_path`](../src/zhengwu_precheck/utils/storage_paths.py)、[材料仓储](../src/zhengwu_precheck/infrastructure/material_repository.py)、[知识上传](../src/zhengwu_precheck/infrastructure/knowledge_repository.py)、[知识索引生成](../src/zhengwu_precheck/core/services/knowledge.py)。读取前仍须通过归属、授权、版本和哈希校验；路径边界检查不能替代本机 ACL，也不宣称防住有本机修改权限者在校验后竞争替换文件的全部情形。
- 默认鉴权：[`staff_api_guard`](../src/zhengwu_precheck/api/staff_dependencies.py)及[应用装配](../src/zhengwu_precheck/main.py)。精确例外仅为 POST `/staff/api/auth/login`、`/staff/api/auth/refresh`、`/staff/api/auth/logout`。公开事项咨询和静态页面保持原可访问范围；个人材料和工单仍要求本人登录及所有权检查。
- 回归：[`test_security_boundaries.py`](../tests/test_security_boundaries.py)。包括正常启动无 admin、页面不显示公开口令、正式预检拒绝公开示例口令且不修改账号、全部现有后台业务 API 匿名拒绝、未来漏配路由默认拒绝、路径及目录联接约束、固定排序与隔离数据验证。
