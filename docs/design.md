# 政务易办设计说明

政务易办面向办事人和工作人员，提供办事指南咨询、材料辅助预检与人工工单协同。本文件概述系统设计，并作为详细设计文档的统一入口。

## 产品范围

办事人通过适配手机的网页描述问题、确认事项、上传材料、查看辅助提示，并在明确确认后提交人工工单。工作人员通过后台维护知识与规则、审核发布版本、处理工单及开展授权审计。

首期围绕居住证申领和个体工商户设立登记两类事项，使用明确标注的虚构示例资料验证流程。预检提供准备性提示，正式申请的受理、审批及办结由原政务系统和法定流程承担。

## 技术与代码组织

系统采用Python、FastAPI和SQLite，网页使用服务端模板及JavaScript；指南问答结合BM25、FAISS与可配置模型服务。

源码统一放在`src/zhengwu_precheck/`：

| 位置 | 职责 |
| --- | --- |
| `main.py` | 应用创建、模块装配与启动入口 |
| `settings.py` | 运行设置与环境变量读取 |
| `api/` | 请求结构、身份依赖与接口路由 |
| `core/` | 指南问答、材料预检、智能体及其他业务服务 |
| `infrastructure/` | 数据库访问、文件引用、配额与备份等基础设施 |
| `utils/` | 文档提取、流解析及其他通用工具 |
| `templates/`、`static/` | 办事人和工作人员页面、样式与交互脚本 |

## 关键设计约定

- 公开咨询与个人业务分别校验身份；工作人员操作同时受岗位、事项范围和记录授权约束。
- 事项选择、材料处理与工单提交保留明确的本人确认和共享范围。
- 知识与规则按版本审核发布，历史记录保留当时使用的版本及依据；依据不足或规则冲突时转人工处理。
- 真实资料、凭证及生产运行数据保存在仓库外；仓库中的配置与数据用于非机密配置和示例示例。

## 工作人员岗位入口

工作人员登录后由服务端按当前岗位授权生成首页、功能卡片和导航，各业务页沿用同一组岗位入口。窗口进入窗口受理工作台，业务审核员进入业务审核工作台；业务负责人、监督员、热线、工程师和主任分别进入业务维护、监督审核、热线服务、平台运维和主任工作台。

窗口接收公共队列，业务审核员接收转交的专业异常并分派。审核员不承担规则发布签核；规则草稿由业务负责人维护并提交监督员审核。热线查询进度，工程师查看技术状态，主任处理明确升级的工单。界面只展示岗位相关且已获授权的功能，不展示全局开发批次安排或其他岗位的工作空间。多岗位账号明确显示已获授权的职责，功能入口去重。

页面入口与岗位权限共同维护，记录访问仍受事项范围、处理关系和共享授权约束。具体入口与验证说明见[岗位工作台调整说明](岗位工作台调整说明.md)。
