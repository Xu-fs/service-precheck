# 智能体、材料与人工协作运行说明

日期：2026-10-31。范围为本地教学版本；只使用明确虚构的资料。实现承接补齐路线设计，不替代真实政策签核或正式审批。

## 办事人流程

1. 启动方法见根目录README。匿名用户可在首页查询教学指南，登录后进入`/assistant`。
2. 选择事项与情形，查看并确认当前规则。刷新恢复本人案例；登录身份变化后重新建立或恢复本人案例，不自动接管匿名历史。
3. 两事项预检须先启用各自候选教学指南。按[材料说明](材料基础实现与验证.md)上传、处理、提交审核、审核及发布；仓库文件存在不等于已经发布。
4. 上传PNG/JPEG/PDF时逐份确认是虚构教学资料并授权。默认可主动转录字段；`ZHENGWU_TRUSTED_TEACHING_MATERIALS=true`仅允许受控可信教学识别。识别文字及低置信度均需人工核对。
5. 根据当前材料集合执行辅助预检。结果限于清单问题和待核实信息，不判断证件真伪、资格或批准。事项、规则、材料或授权变化后重新确认及预检。
6. 逐份选择共享材料，按需关联预检。填写问题后准备草稿，预览正文、材料版本、历史预检摘要及所选异常，再明确确认提交。
7. 在`/my/tickets`查看结果、答复和站内消息；继续补充或本人确认完成。普通咨询也可直接从本页准备草稿，无需先完成预检。

四类待人工核实异常为有效期疑问、依据不足、规则版本冲突和关键服务不可用。它们可独立准备人工咨询草稿，不以预检完成为前提。修改草稿可明确移除材料、预检或异常关联，保存会使旧确认失效。

## 服务端约束

六工具固定为`search_guidelines`、`recommend_matter`、`check_materials`、`prepare_ticket_draft`、`create_manual_ticket`、`get_ticket_status`。模型选择工具，服务器提供身份与处理器；模型不能签发事项或提交确认。每轮最多`ZHENGWU_AGENT_MAX_CALLS`次，默认6、最大12，另有总时限与单工具时限。

事项确认绑定案例版本和规则快照；提交确认绑定本人、草稿版本、内容哈希、共享范围和有效期。`POST /tickets`只接收已确认草稿信封，与原生页面及工具共用同一创建事务。重复提交返回原工单；相同操作标识不能改绑其他草稿。响应不明先查询原结果，保留原操作标识。

材料预检在计算完成后再次校验规则、选择及材料集合。工单共享冻结材料版本；撤回或修改后不再允许下载该旧版本。工作人员只查看明确共享且符合岗位及处理关系的数据；热线保持摘要边界。预检关联提供历史摘要，未共享材料的字段不会随预检自动全部开放。

历史表`tickets.precheck_id`保持NULL，新增预检、异常与材料关联保存在草稿及`agent_submissions`映射中，由统一详情服务读取。正式办件没有接入，不生成假办件编号。

未知事项保存为`unassigned/manual-triage`，需要显式`unassigned`岗位授权；普通通配事项不自动取得其访问权。工单接手、转派、48小时首次答复、14天等待、7/14天提醒及默认完成规则沿用既有实现。

## 运维和验证范围

LLM及嵌入经过同一持久预算入口，同时限制全局、操作者、服务及操作者与服务组合；后台知识处理归属上传操作者。本地OCR另有同机处理配额。默认不外发材料正文和工具中的个人字段，脱敏规则不能替代人工确认数据范围。

验证包含真实FastAPI/SQLite/FAISS审核发布链、原生工单确认、Chrome助手材料流程及真实本地中文OCR。外部模型HTTP使用明确替身。30题夹具是按已保存分类重建的可执行合同，未逐字恢复缺失的历史原题，也不代表30题真实模型端到端成功。

最终测试结果、审查处理和实际新增目录树见[执行记录](superpowers/completion-progress.md)；发布、备份及隔离恢复步骤见[运维说明](运维部署与恢复.md)。真实外部服务、生产负载、真实政策与Windows非教学任意文件隔离仍待完成。
