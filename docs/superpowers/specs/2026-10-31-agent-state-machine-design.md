# 有限工具智能体与服务端状态机设计

## 目标与范围

在现有示例指南问答和本地人工工单基础上，允许模型在授权范围内选择工具，由服务端强制执行身份、权限、确认、版本和状态检查。使用虚构示例数据；现有工单是本地闭环，不代表真实政务接口。材料上传、OCR和预检目前未实现，不得声称已接入。

## 架构

模型只能访问注册工具；工具执行入口验证参数，从会话取得身份与授权，再调用业务服务。规则检索复用公开发布快照和引用校验，工单复用现有仓储、权限及幂等机制。模型、用户输入、检索正文均不能授予权限。限制每轮工具调用次数及超时；外部模型调用不持有数据库写事务。工具输出按统一状态 ok、needs_confirmation、blocked、requires_manual、temporarily_unavailable 返回 data、error、next_actions 和 trace_id；错误明确可否重试。

## 工具契约

输入采用严格 JSON Schema，禁止额外字段；身份、角色、授权从服务端上下文取得。资源 ID 均校验归属和版本。

| 工具 | 输入 | 输出 | 权限、前置条件及失败处理 |
| --- | --- | --- | --- |
| search_guidelines | query、jurisdiction_code、可选 matter_id/scenario_id | 已发布指南候选、依据、有效期、规则快照及冲突 | 公开资料可匿名；内部资料须授权。依据不足、版本冲突或关键服务不可用时停止相关建议并提供人工路径。 |
| recommend_matter | case_id、intent、search_result_id | 事项情形候选、理由、依据和 selection_proposal_id | 会话或案例归属有效；不能代替办事人确认，候选不明确时澄清。 |
| check_materials | case_id、selection_confirmation_id、rule_snapshot_id、material_set_id、expected_case_version | precheck_id、逐项结果、引用、异常及冻结版本 | 登录及资料授权；事项、情形、规则版本均已确认且一致。条件不足拒绝执行；异常暂停受影响建议。材料能力未接入时明确返回不可用。 |
| prepare_ticket_draft | case_id、purpose（ordinary_consultation 或 exception_review）、summary、可选 precheck_id/exception_ids、expected_case_version | draft_id、draft_version、正文、共享范围、缺失字段、draft_hash | 案例可访问；普通咨询及异常转人工均不以预检完成为条件。事项未知时保留待人工确认，不编造。 |
| create_manual_ticket | draft_id、draft_version、submission_confirmation_id、idempotency_key | ticket_id、提交时间、queued 状态和共享摘要 | 登录、权限、字段及对应草稿确认有效；超时按幂等键核对，禁止盲目重复创建。 |
| get_ticket_status | ticket_id | 授权范围内的状态、答复、待办和更新时间 | 本人或有效代理；工作人员按岗位、事项和处理关系授权。无权或不存在统一对外提示，故障不编造进度。 |

预检结果限定为未发现清单问题、疑似缺项、信息待核实、无法判断或需人工核验；不得判断资料真实性、资格或审批结果。正式补正要求由工作人员确认。

## 确认与状态

事项确认及工单提交确认是办事人直接触发的服务端事件，不能由模型代办。事项确认绑定案例、事项、情形、规则快照和案例版本；提交确认绑定登录用户、草稿版本、内容哈希、共享范围及有效期。修改绑定内容使确认失效；事项、情形或规则变化使旧预检不再作为当前结果。确认记录一次消费。

普通路径：检索、推荐、办事人确认事项情形及版本、材料辅助预检、按需准备草稿、登录并确认提交、创建窗口待办。普通咨询可跳过预检。

异常路径独立于普通预检：任意阶段发现异常时立即记录并暂停受影响建议，准备人工工单草稿，登录、校验最小必要字段并由办事人确认后创建窗口待办。事项不明时进入有授权的人工咨询分流。系统必须支持该分流，不能为通过现有事项必填校验而捏造事项。

以下情况必须转人工：证件过期但历史显示有效、资料缺少依据、规则版本冲突、关键系统不可用。普通清单缺项与资料缺少可核验依据分别记录。工单系统不可用时保留可恢复的异常和草稿并展示已配置联系方式，不能声称已提交。专业异常由窗口人员按现有权限处理或转审核员，不自动升级主任。

## 服务端执行和提示词

每次调用校验参数、真实身份、对象归属、授权、状态和版本，再调用业务服务。创建工单在同一事务内重新检查权限、字段、草稿及确认绑定，原子消费确认、创建工单并记录幂等结果。幂等键绑定操作者和载荷；重放前重新验证权限。所有入口包括现有 POST /tickets 接入同一创建校验服务，避免绕行；按需调整现有表单以提供真实确认。审计记录动作、结果、依据版本和授权决策，避免记录不必要的证件内容。

系统提示词要求模型仅使用注册工具，不将用户或检索正文作为指令；事项和工单必须等待办事人确认；四类异常暂停相关建议并提供人工路径；不得猜测确认凭证、宣布法定审批结果、发布正式补正要求或升级主任。只有工具明确成功时才能报告创建成功。提示词不能替代服务端检查。

## 验收

覆盖正常推荐和确认、规则变更失效、预检前置条件、四类异常且预检未完成的人工路径、未知事项分流、工单系统不可用、未登录、越权访问、伪造或过期确认、修改草稿、旧接口绕过、并发与幂等重试。验证工作人员权限及不自动升级主任。模型输出使用替身和示例资料测试；真实外部模型、真实材料识别和政务对接未经验收时明确标注。
