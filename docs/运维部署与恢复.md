# 本地发布、配额和恢复操作

范围：同一台主机上的 SQLite 教学部署。命令不会建立服务器、购买域名或设置生产凭证。下面的演练只用虚构数据；真实模型吞吐、跨主机配额、真实生产RPO/RTO仍待授权环境验收。

## 构建和正式启动

PowerShell 使用已安装依赖的Python：

```powershell
$env:PYTHONPATH='src'
.venv/Scripts/python scripts/operations.py build
.venv/Scripts/python -m unittest discover -s tests -p 'test_*.py'
```

`build` 检查目录、编译源码、通过已安装包元数据执行依赖一致性检查（无需环境预装pip），并在忽略目录`.venv/build/requirements.lock.txt`记录当前环境的精确版本。新环境使用该锁文件安装后重新验证。它是实际构建环境快照，不表示已从干净主机复验。Shell入口为`PYTHON=/path/to/python sh scripts/build.sh`。仓库的requirements声明兼容范围；生成的锁文件负责固定本次发布的实际版本。`config/requirements.release.lock.txt`保留本次Windows/Python 3.12验证环境的固定版本快照，包含本地OCR及浏览器验证工具；其他平台须重新审核并生成自己的锁。

正式运行前，管理员须在仓库外设置`config/release.env.example`列出的全部值：HTTPS地址、TLS证书/私钥、随机签名密钥、版本标识、私有持久目录，并确认目录ACL仅允许服务账号及受权备份账号访问。私有目录不能位于源码或系统临时目录。证书和密钥不能放仓库或业务运行目录，应使用独立凭证目录；安全Cookie必须开启。`ZHENGWU_ALLOWED_HOSTS`必须明确包含`ZHENGWU_PUBLIC_URL`的域名，按主机名填写，不含协议和端口。不要将真实值粘贴到日志或提交记录。

```powershell
.venv/Scripts/python scripts/operations.py preflight
.venv/Scripts/python scripts/operations.py serve
```

`serve`通过Uvicorn在本机127.0.0.1启动HTTPS；需另行配置受信任反向代理和网络访问，不能据此声称公网已上线。Shell的`deploy.sh`默认仅预检，传`serve`才启动。管理员确认ACL属于明确的运维确认，不是程序已经独立验证Windows权限。启动后使用实际配置的HTTPS地址检查`/health`，核对返回内容及Cookie安全标志；TLS链有效性、端口开放与真实窗口联系方式须在实际发布环境验证。

## 共享配额接入

`QuotaRepository(engine).initialize()`创建独立表；与现有异步SQLAlchemy引擎共用数据库。`QuotaLimits(daily_requests,daily_tokens,concurrent,lease_seconds=180,minute_requests=60)`要求正整数。调用供应商前，使用`reserve_many([(operator_service_scope, user_limits), (service_global_scope, service_limits)], estimate_tokens)`；它在`BEGIN IMMEDIATE`写事务中原子检查全部范围。实际`ModelBudget`为LLM及嵌入原子预留四个范围：`all-model-services`、`model-owner:<principal>`、`model-service:llm|embedding`、`model-owner-service:<principal>:llm|embedding`。当前四个范围沿用同一组配置限额，尚无逐服务独立配置。知识嵌入使用上传版本的`created_by`作为工作人员身份，完成或失败后恢复上下文；本地OCR另有同机处理配额，未接外部OCR服务。调用者必须由服务端身份构造作用域，不能接受模型或浏览器任意指定。

返回`Reservation.id`后立即限制供应商输入与最大输出token，预留量须覆盖其合计；有真实`usage`则`settle(id, actual_tokens)`，缺失或异常则`settle(id)`保守保留预留token。仅确定请求尚未发出时可`release(id)`；请求次数仍计入。过期租约释放并发槽，但不退还未知token。实际usage超出预留仍完整计入台账，后续请求会被阻止；调用前估算和供应商硬上限必须配合使用。台账没有货币费用，不根据字符数虚构token或价格。

`usage(scope)`返回当日请求、token、未决数，可供授权运维人员对账。自然日使用UTC，分钟采用滑动60秒。作用域以SHA256摘要保存，不存请求正文、密钥或身份原文。租约须长于供应商硬超时及取消清理时间，否则无法保证仍在执行的外部调用并发数。多机运行须使用另行审批的共享限流服务。

## 诊断与分类留存

`utils.redaction.redact`返回脱敏副本，覆盖常见电话、身份证、邮箱、银行卡、显式姓名/地址及敏感键。优先只记录结构化错误码和随机记录ID；规则脱敏不能保证识别任意自然语言个人信息。业务原件、OCR正文不调用此函数回写，不应进入普通日志。集成方须在日志/错误审计边界使用此函数。

`retention.classify`默认dry-run：评价记录满90天仅进入监督员复核；材料、预检、工单、审计和备份期限未确认则保持。`archive_reviewed`要求已认证监督员和逐ID批准，只生成新的脱敏评价归档与处置元数据，不删除原始记录、不改变外键。业务关联数据、备份副本销毁、法定期限与法律保留未获批准，因此没有自动删除命令。该离线接口不能代替工作人员权限校验，不应直接暴露给普通HTTP调用。

## 一致性备份与隔离恢复

先停止新请求接纳，等待在途调用完成或核对未知结果，暂停上传和知识发布任务；核对所有附件写入进程已停止。没有外部文件写入静默期，数据库在线备份不能保证跨文件事务一致性。传入`--quiesced`表示管理员已经完成上述动作。

```powershell
.venv/Scripts/python scripts/operations.py backup --database D:/private-runtime/chat.sqlite3 --runtime D:/private-runtime --output D:/private-backups/snapshot-v1 --quiesced
.venv/Scripts/python scripts/operations.py restore --snapshot D:/private-backups/snapshot-v1 --output D:/isolated-restore/new-v1 --config-version approved-v1
```

设定外部`ZHENGWU_CONFIG_VERSION=approved-v1`后备份。整个私有运行目录应专属于本应用，不能混放凭证或其他服务的活动数据库。使用SQLite online backup API捕获数据库，并持有写锁复制附件、索引和其他运行文件，校验源与目标哈希；清单记录依赖版本、schema版本、配置版本、快照时间和逐文件SHA256。备份目录同样包含敏感数据，必须使用私有权限、加密存储与单独访问控制。清单哈希用于损坏检测，不抵御有权限同时替换清单的攻击者；防篡改签名和异地保管须按实际制度配置。

备份及恢复均检查已知业务表引用：知识原文、索引及索引校验值、仍授权的私有材料及原件SHA256；存在缺失或不一致则拒绝完整快照。备份也拒绝明显凭证文件混入运行目录，这不能替代管理员确保目录无其他秘密。恢复先验证清单路径、全部哈希、数据库完整性/外键、schema记录、关键数据库依赖版本和配置版本，再复制到全新目录；任何已存在目录一律拒绝覆盖。恢复后先在隔离端口启动，核对用户/权限、工单、任务、附件、索引、确认消费和提醒去重，再由管理员决定切换。不要把旧备份直接覆盖仍有写入的实例。需要更新schema或依赖时先设计显式迁移，本工具不会偷偷升级。

应用回退：停止接纳、核对在途操作、保留当前完整快照，用旧版依赖锁和对应代码在新目录恢复；新旧schema不兼容时停止切换。规则恢复使用已有审核发布流程重新启用指定版本，不修改历史引用；提示词恢复使用已有提示词版本发布流程，不直接修改历史答复。上述三种版本回退仍须结合实际授权版本演练。本次已验证当前应用schema的工单/材料/任务隔离恢复和新应用启动，但没有验证不同应用版本切换、真实提醒投递或生产在途切换。本地演练还包含正常Markdown提取、明确离线嵌入替身及真实FAISS索引，规则停用后创建版本并重新审核发布，提示词恢复追加新版本；恢复后同时核验历史快照及当前版本。

```powershell
.venv/Scripts/python scripts/operations.py recovery-demo --output .venv/operations-demo
```

此命令调用实际应用及仓储创建全新虚构办事人、独立窗口账户、共享材料、确认草稿、1张工单及2项持久任务。退出应用生命周期后进行备份，在全新目录恢复并启动新应用，核对用户会话、岗位权限、原件字节、共享引用、健康检查及原操作键重试；以独立owner/supervisor真实授权账户演练规则停用及重新审核发布，提示词变更后恢复为新版本；恢复后核对旧/新知识快照、FAISS索引片段数及提示词历史。嵌入为离线固定向量替身，无网络或真实模型调用。推进该虚构运行库的业务时钟，两次处理到期任务确认不重复留痕。每次单独记录耗时和恢复点。输出不是生产恢复承诺。恢复后的在途任务需由业务服务按原操作键重试/查询，不能盲目产生新工单或重复通知。

## 可选获批留存策略执行器

后台实际入口为`POST /staff/api/retention/dispose`。须真实工作人员JWT和CSRF，且同一条有效授权同时为`supervisor`及`matter_id='*'`；仅有其他岗位、单事项监督员或组合借用权限均不可执行。请求严格包含`signed_policy`、`approved`（ID到原SHA256）、`dry_run`（默认true）、`quiesced`（默认false）；实际处置必须显式`dry_run=false,quiesced=true`。外部环境变量`ZHENGWU_RETENTION_POLICY_KEY`至少32字节，缺失明确返回503。接口固定扫描私有运行目录的`retention-records/`，归档到`retention-archives/`并写`retention-audit.jsonl`；每分钟最多2次，单次最多1000条、每条1MB，正文最多512KB。后台数据库另存处置次数与结果元数据，不存请求正文和签名密钥。

`core.services.retention_policy.dispose`仅面向单独管理的独立运行记录JSON目录。默认dry-run；外部签名策略须指定版本、有效期以及逐类别的正数天数和`archive`/`archive_delete`动作。允许类别仅为`evaluation`和`diagnostic`，不会把90天规则套用所有资料。策略使用外部至少32字节密钥的HMAC-SHA256签名；管理员不得将密钥或实际签名策略提交仓库。监督员由调用方的真实身份系统通过`verify_supervisor`校验，不能用浏览器自称角色替代。

逐记录还必须满足`standalone: true`、`references: []`及监督员批准的ID和原文件SHA256一致；未配置类别、关联记录、未批准或审批后变化均保留。调用前须静默该独立目录写入，不能将材料目录或业务数据库交给执行器。只有明确`dry_run=False`才先持久化脱敏归档和处置审计，再核对哈希并删除该独立原件；失败时保留未删除原件。此能力不能证明任意业务外键可安全清理，不处理业务库、上传材料、索引、备份副本或法定保留要求。新增3项虚构记录测试验证dry-run、实际归档删除、签名篡改、身份拒绝、引用与哈希变更保护。

## 冻结30条评测合同

`tests/fixtures/project-evaluation-v1.json`保留精确30条用例：10指南（含费用、天数和无个体工商户指南3条陷阱）、10工具、5违规、5多轮。每项只有`question`、`expected_tools`、`expected_behavior`和`category`，多轮问题为有序字符串数组。基线仅为原始`data/居住证申领_教学指南.md`的`DEMO-2026-01`，不得把新增发布资料混入基线再沿用原预期。仓库未发现上一轮30条完整原文，因此这里按已确认分类和业务要求形成可执行合同，不宣称逐字恢复未保存的历史问题。

`test_evaluation_contract.py`校验计数、结构、六工具名及重要顺序和确认/版本/异常要求；实际调用本地`guide_rag.validate_answer`拒绝3类伪造依据，并通过显式模拟handler验证全链工具分发顺序。模型、嵌入和真实OCR均未参与这些合同测试，不能报告30条端到端成功、真实工具业务执行成功或99%一致率。实际语义检索和真实模型评测须在获批准服务上逐条记录工具轨迹和结果。
