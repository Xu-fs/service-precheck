# 政务材料预检与服务协同设计框架

本文记录需求讨论中已确认的范围和业务概念，仍处于需求分析阶段，不代表完整设计已获确认。

## 商业目标与当前条件

- 项目背景固定为“云州市便民服务中心”，围绕该中心的办事人、窗口工作人员、业务审核员、政务平台工程师、数据与流程监督员、热线服务负责人及服务中心主任展开需求分析。

- 课程考核要求体现商业化，目标是形成面向真实政务客户的商业方案和可验证产品。
- 当前尚无已接洽客户、已授权接口或真实业务数据；后续面向真实客户开展业务及接口核实。
- 产品需要考虑与客户现有政务系统对接；具体系统、接口能力、账号体系和部署条件待客户确认，当前不视为已经具备。
- 当前验证使用明确标注的虚构或脱敏示例资料；合成访谈中的预算、基线和目标仅为案例条件，不代表实际客户承诺。
- 产品验证与客户试点验收分别记录；真实业务效果须在客户授权及约定统计口径后验证。

## 已确认商业交付方式

- 面向云州市便民服务中心采用“一次性实施费用＋年度运维服务费”的商业方案。
- 优先在客户指定环境部署，材料和业务记录由客户控制；当前产品验证使用虚构材料。正式部署前核实客户网络、算力、访问入口和外部模型调用条件，不将客户控制存储等同于已获外发材料授权。
- 真实材料仅由客户环境内或客户批准的模型服务处理；未经授权不得发送至外部服务。该边界同时适用于原图、PDF、识别文本及包含材料内容的模型请求。客户批准的服务仍须遵守授权的数据范围。
- 一次性实施范围包含部署、两类事项配置、系统对接和培训；具体对接内容及可交付条件以客户授权和接口核实结果为准，不预先承诺未核实接口。
- 年度运维包含系统维护、规则更新支持及效果复测；规则的业务维护、审核和发布权限仍按既定岗位分工执行。
- 新增事项或新增接口另行约定范围与费用，不默认纳入基础服务。
- 具体报价、年度服务额度和成本测算尚未确定；报告中的18万元为案例预算，不直接作为产品报价或已获订单。

## 已确认范围

- 同时提供办事人端和工作人员端。
- 办事人端采用适配手机的网页，工作人员端采用面向电脑操作的网页。
- 本产品负责材料预检与人工工单协同；正式申请的受理、专业审批及办结由原政务系统和法定流程承担。
- 本产品内保存的预检记录、人工工单及其处理结果，不代表正式申请已经提交、受理或批准。与原政务系统的跳转、数据传递和状态查询方式待接口条件确认。
- 普通咨询无需登录；上传材料、提交人工工单和查询个人记录需要登录。
- 办事人可在正式申请前进行自助预检，准备性提示即时展示；正式补正要求由工作人员确认后发出。
- 办事人可以上传图片或PDF进行材料预检，也可以直接用文字描述问题；不以先上传材料作为咨询前提。
- 办事人不清楚所属事项时，系统根据问题描述推荐事项，由办事人确认后，再使用对应清单进行预检。
- 无法解决的问题转为人工工单，统一进入窗口待办，由窗口接手处理或分派给其他岗位。
- 窗口统一接收所有工单；普通问题由窗口处理或分派，专业异常交业务审核员，由其分派给实际处理人。是否升级服务中心主任由业务员手动选择，系统不自动升级。转出方在接收人确认接手前仍保留待办责任。
- 工作人员处理时限为1个工作日内接手、工单提交起48小时内首次处理答复；48小时连续计算，包含周末及节假日，接手或转派不重置首次答复期限。该答复时限不等于保证问题已解决，也不替代正式审批时限；接手期限不顺延48小时答复期限。
- 首期通过站内消息和工单详情向办事人反馈补充信息请求及处理结果，不接入短信通知；消息发送不等于办事人已阅读或问题已解决。
- 业务员回复后即启动14天计时，不区分补充材料请求或处理结果；不采用“只有给出处理结果才启动计时”的建议。办事人确认问题已解决后关闭，仍有问题可在原工单继续补充并交由工作人员处理。
- 办事人在工单关闭前继续回复或补充材料时，停止本轮自动关闭计时并取消尚未发送的本轮提醒，工单等待业务员处理；业务员再次回复后，重新计算完整14天及第7天、第14天提醒，不沿用上一轮剩余时间。
- 业务员回复后，第7天和第14天分别通过站内消息额外提醒一次；第14天提醒后保留至当天结束，届时仍未确认且没有办事人后续回复或补充材料，则自动关闭，默认已完成。用户已明确采用该默认完成规则及当天结束时关闭的安排。
- 完成记录区分“办事人确认完成”和“超时默认完成”；二者均属于已完成，但默认完成不能表述为办事人已确认。

## 清单与规则维护权限

- 业务负责人维护材料清单与预检规则，提交数据与流程监督员审核，审核通过后发布生效版本。
- 窗口和热线人员可以反馈规则问题，不能直接修改已发布规则。
- 已发布规则发生修改时形成新版本；预检记录保留当时使用的版本及依据，不以新版本覆盖历史引用。
- 遇到版本冲突时转人工处理，不由系统自行选择较宽松条款或合并规则。

## 已确认的验收层级

### 首期验收要求

- 清单解释一致率不低于99%；应依据已确认的事项清单与适用版本评测，不以模型自评分作为验收依据。
- 不输出批准结论，权限边界、四类人工兜底及建议与人工处理留痕可核验。
- 一致率的评测单位、标准答案签核人、样本量、统计周期及排除规则尚待约定；当前不声称已经达到99%。

### 业务改善目标

- 补正率由案例基线36%降至18%，材料清单解释平均时长由案例基线12分钟降至5分钟。
- 经试点前后对比验证，不将上述目标直接写成已经达成的收益或无条件商业承诺；先核实同范围基线、计时起止与样本可比性。
- 工单默认完成、通知发送及正式办件办结分别计量；超时默认完成不能替代实际问题解决的证据。

### 真实客户接入前待核实

- 接口与主编号映射、独立账号授权、缺字段补录负责人及同步具体时点。
- 客户环境、模型服务、真实材料留存期限与到期处置执行人。
- 验收样本及标准答案、误判责任、停止试点的具体阈值与复盘分工。
- 实施及年度运维成本、服务额度和最终报价。

## 数据留存与到期处置

- 材料原件、预检记录和工单记录分别按客户规定配置留存期限，当前不擅自固定天数，不统一套用90天。
- 依据报告 f43，本轮评价记录暂保留90天，到期由数据与流程监督员复核后决定删除或归档；具体组织规则及处置执行人仍待真实客户确认。
- 工单关闭与材料删除分开处理，关闭不触发材料立即删除；到期处置应保留必要的处置审计记录。

## 首期验证事项

### 已确认预检深度

- 材料齐全性：对照办事人确认的事项、适用情形及清单版本，检查必需材料是否齐备。
- 材料可读性与信息完整性：检查上传图片是否清晰、必填信息是否缺失；识别不清时请求补充或转人工，不将识别失败直接视为材料缺失。
- 跨材料信息一致性：比对姓名、地址、日期等相关信息，提示差异并引用对应材料；无法解释的差异转人工核对，不直接判定材料无效。
- 首期不判断证件真伪、法定资格或最终审批结论，由有权限人员依照正式业务流程判断。

## 两端业务流程

办事人描述问题或选择事项 → 必要时系统推荐事项、办事人确认 → 问题解答或上传材料自助预检 → 展示准备性提示 → 无法解决则转人工工单 → 窗口接手处理或分派 → 反馈办事人。

仅凭描述缺少判断依据时，应引导补充必要信息或材料，不将描述视为材料已核验。申请前的工单关联预检记录，正式提交申请后再关联办件。

## 业务术语

**自助预检**：办事人在正式提交申请前，对准备材料进行的辅助检查。结果是准备性提示，不具有批准效力。
_Avoid_：自动审批

**办件**：办事人针对某一办事事项正式发起的一次具体办理申请。申请前的自助预检不等于已经形成正式办件。
_Avoid_：工单、预检记录

**预检记录**：一次自助预检所涉及的材料、提示和问题记录。正式申请前产生的问题可以关联该记录。
_Avoid_：正式申请、审批结果

**人工工单**：针对自助预检无法解决的问题发起的人工处理任务，先进入窗口待办，再由窗口接手处理或分派。工单关闭不等于办件办结。
_Avoid_：办件、审批申请

**待办事人确认**：业务员已回复，正在等待办事人反馈或确认的工单状态；回复可以是补充材料请求或处理结果。
_Avoid_：已解决、已关闭

**准备性提示**：即时向办事人展示、帮助其准备或调整材料的辅助说明。
_Avoid_：正式补正通知、批准结论

**正式补正要求**：由工作人员确认后，向办事人发出的材料补充、更换或说明要求。
_Avoid_：自助预检提示
