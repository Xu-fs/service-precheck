# 本地示例预设账号

以下均为虚构的示例演示账号，密码统一为 **`123456`**，不得用于真实业务部署。

| 角色 | 账号 | 主要用途 |
| --- | --- | --- |
| 办事人 | `demo_citizen` | 个人咨询、示例材料预检、本人工单 |
| 窗口工作人员 | `demo_window` | 知识查阅、工单处理和转派 |
| 业务审核员 | `demo_reviewer` | 工单审核处理和分派 |
| 业务负责人 | `demo_owner` | 知识及规则草稿维护、提交审核、反馈处理 |
| 数据与流程监督员 | `demo_supervisor` | 审核发布、提示词管理、授权范围内的审计 |
| 热线人员 | `demo_hotline` | 知识查询、工单进度、获授权的会话摘要 |
| 政务平台工程师 | `demo_engineer` | 系统运行状态 |
| 服务中心主任 | `demo_director` | 升级工单及获授权的会话 |

办事人使用 [首页](http://127.0.0.1:8000/) 的个人咨询登录；其余七类账号使用 [工作人员登录](http://127.0.0.1:8000/staff/login)。

## 初始化与启动

在项目根目录执行一次：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/create_demo_accounts.py
```

然后双击根目录的 `启动网页.bat`。如果初始化前已有服务在运行，请先在原启动窗口按 `Ctrl+C`，再启动，以便加载工作人员登录密钥。普通服务启动不会自动创建或重置演示账号。

初始化使用与应用相同的 `Settings`：优先使用 `ZHENGWU_RUNTIME_DIR` 指定的仓库外目录；未配置时使用系统临时目录下的 `zhengwu-web`。账号及密码哈希保存在该目录的 `chat.sqlite3`，示例账号归属记录保存在 `demo-accounts.json`。若清理了运行目录，需要重新初始化；如需长期保留，可在初始化和启动前设置同一个稳定的仓库外运行目录。

若环境中没有 `ZHENGWU_STAFF_JWT_SECRET`，初始化会在同一个运行目录生成随机的 `staff-jwt.key`，后续启动复用。显式环境变量优先，不在仓库保存真实密钥。

重复初始化只复用归属记录中匹配的演示账号，补齐对应事项授权，不重置任何密码。遇到不属于本工具的同名账号会停止，保留原账号。普通真实账号仍通过 `scripts/create_user.py` 的交互方式创建，保留其至少 12 字符的密码要求。

## 权限说明

登录后显示本账号的岗位工作台。`demo_window` 看到“窗口受理工作台”和“窗口工单受理”，`demo_reviewer` 看到“业务审核工作台”和“专业审核与分派”；其余账号也只显示各自岗位相关入口。工程师的页面入口为 `/staff/system`。详见[岗位工作台调整说明](岗位工作台调整说明.md)。

需要演示用户发消息、逐级审核及确认结案时，按[两个完整流程预设案例](demo-cases.md)准备工单。账号初始化与案例创建分别执行。

每个工作人员账号只有表中单一岗位，事项范围限定为“居住证申领”和“个体工商户设立登记”。未授予通配事项或“人工咨询分流”权限。查看具体工单、会话或材料仍需既有的处理关系、共享同意及逐条授权；初始化不会生成业务记录、发布规则或开放所有历史数据。

业务负责人和监督员用于分别演示提交与审核发布。工程师只能看技术状态，主任也不是全权限管理员。知识库或工单为空时属于尚未录入、发布或授权数据，与登录是否成功分开判断。
