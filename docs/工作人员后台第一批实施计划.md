# 工作人员后台第一批实施计划

依据：2026-10-31用户确认的后台页面及接口清单。只实现第一批，后续知识发布、提示词、审计和工单均不提前伪装为已完成。

## 范围与文件

- `core/staff_permissions.py`：七类岗位、权限及事项范围决策；同一条岗位授权必须同时满足权限和事项，不能交叉拼接。
- `infrastructure/staff_repository.py`：岗位、范围、会话、记录授权及权限操作留痕。
- `utils/staff_jwt.py`：固定算法、签发方、用途、过期及必需声明校验。
- `core/services/staff_auth.py`：JWT登录、刷新轮换、撤销与实时权限检查。
- `api/staff_dependencies.py`、`api/routes/staff.py`：SSR与API入口、独立CSRF、记录授权。
- `templates/staff/`、`static/css/staff.css`：登录、工作台、当前授权及后续功能说明；Jinja2渲染，无SPA。
- `scripts/staff_access.py`：由维护人员在仓库外凭证配置环境中分配/撤销岗位与记录授权，无网页自助提权。
- `tests/test_staff.py`、`tests/browser_staff.py`：认证、权限、历史数据兼容及浏览器验证。

## 验收重点

无JWT/错误用途/过期/撤销均拒绝；现有办事人Cookie不能登录后台；岗位与事项授权不能拼接；撤销岗位立即失效；刷新令牌仅能用一次；记录ID不能绕过归属授权；已有会话与登录在新增表后保持可用。后续页面无成功提交假流程，未配置JWT密钥时只禁用后台，不破坏公开咨询。
