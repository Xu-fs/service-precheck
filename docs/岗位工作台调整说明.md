# 岗位工作台调整说明

日期：2026-11-01。

## 问题与依据

原后台首页共用第一批通用模板，展示全部开发批次和全局功能介绍；窗口与审核员的工单入口也使用同一名称和筛选项。岗位菜单已有权限筛选，但首页内容没有体现职责差异。

本次依据《设计框架》的工单分工、规则维护权限和材料查看边界，调整页面展示。登录仍进入 `/staff`，由服务端按实时岗位授权生成各自的首页和导航。

## 页面分工

| 岗位 | 首页 | 可见功能入口 |
| --- | --- | --- |
| window | 窗口受理工作台 | 窗口工单受理、办事知识库、规则与清单、规则问题反馈 |
| reviewer | 业务审核工作台 | 专业审核与分派、办事知识库、规则与清单 |
| owner | 业务维护工作台 | 办事知识库、规则与清单、审核发布进度、规则问题反馈 |
| supervisor | 监督审核工作台 | 审核发布、对话与预检审计、提示词模板、办事知识库、规则与清单 |
| hotline | 热线服务工作台 | 工单进度查询、办事知识库、规则与清单、规则问题反馈 |
| engineer | 平台运维工作台 | 系统运行状态 |
| director | 主任工作台 | 升级工单处理 |

以上入口还须满足当前授权动作。窗口保留公共队列；审核员和主任保留本人处理及待接收转派筛选，热线仅提供进度范围查询。事项下拉框也只列当前账号获授权的事项。多岗位账号显示“多岗位工作台”，列明实际职责并对入口去重；多事项授权不重复生成工作台。

知识、规则、发布、提示词、审计与工单页共用岗位导航，不再显示开发批次标签或办事人端入口。移除原首页中已过时的功能状态说明。工程师通过 `/staff/system` 查看现有技术状态接口的数据。

各业务接口仍使用已有的动作、事项和记录校验；本次没有新增岗位授权或创建业务数据。业务审核与监督员的规则审核发布职责分别保留。

## 使用与验证

代码更新后，在原服务启动窗口按 `Ctrl+C` 停止，再双击根目录 `启动网页.bat` 并重新登录。启动脚本会复用仍在运行的服务，因此仅再次双击不会替换已加载的旧代码。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -p test_staff_workspaces.py -v
.\.venv\Scripts\python.exe -X utf8 tests/run_browser_check.py --suite workspaces
.\.venv\Scripts\python.exe -X utf8 tests/run_browser_check.py --suite cases
python scripts/check_structure.py
```

界面回归覆盖七类岗位、同岗位多个事项、明确授予的多岗位账号及各自正常业务页的导航一致性。Chrome验证关闭JavaScript下的岗位首页与入口，并检查手机布局。既有两个虚构案例用于核对窗口、审核员、主任交接及办事人确认结案；模型由测试替身提供，运行库与业务运行目录分离。
